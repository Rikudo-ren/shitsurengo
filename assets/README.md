# assets — osu!風スキン & 低遅延アセット

このフォルダは **入力遅延を増やさずに** カスタマイズするための置き場です。

## タップ音
- `tap.wav` / `tap.mp3` / `hit.wav` / `hit.mp3` のいずれかが存在すれば、それをデコードして即時再生します。
- 無ければコード内で合成した 60ms クリック音（ゼロアセット、最速）を使います。
- **遅延的には合成音が最速**です。ファイルがある場合は初回だけ fetch+decode が入りますが、2回目以降はメモリ上の AudioBuffer なので同等に高速です。
- osu!のように独自のヒットサウンドを入れたい場合はここに置き換えてください。短い（<100ms）WAVが最も低遅延です。MP3はデコードが少し重いです。

## ノーツ画像
- `note.png` : 通常ノーツ
- `note_ln.png` : ロングノーツ頭
- 存在すればスプライトとして使われます。無ければコードで生成する白丸（最速、ネットワーク無し）を使います。
- 画像を使うこと自体で入力遅延は減りません。描画はどちらも `drawImage(pre-rendered canvas)` で同コストです。
- 見た目を osu!スキンのように変えたい場合に置いてください。推奨は 256x256 透過PNG。

## 本当の遅延要因と対策（実装済み）

今回の遅延改善で直した点：

1. **AudioContext**: `latencyHint:'interactive', sampleRate:48000` で生成。デフォルトより出力遅延が小さい。
2. **即時resume**: `press()` 内で `AC.resume()` を await せず即呼出。サスペンド起因の無音を防止。
3. **即時描画**: 入力時に `draw()` を同期的に呼び、次フレーム(16ms)を待たない。体感遅延を削減。
4. **キャプチャフェーズでキー取得**: `keydown` を `capture:true, passive:false` で登録。ブラウザの遅延を除去。
5. **desynchronized canvas**: `getContext('2d',{desynchronized:true})` で表示遅延削減。
6. **タップ音は最短経路**: `gain -> destination` 直結、`AC.currentTime` で即時 start。
7. **アセットのプリロード**: 起動時に `ensureCtx()` と `loadNoteAssets()` をウォームアップ。

### ファイルを同梱する意味

- **タップ音MP3/WAVを同梱**: ネットワーク待ち無し、オフライン動作、音のカスタマイズ。入力遅延自体は合成音と同等か微増だが、体感の一貫性は上がる。
- **ノーツ画像を同梱**: ネットワーク待ち無し、スキン統一。描画コストは合成と同等。入力遅延は変わらないが、ロード時のカクつきが減る。

結論: **osu!のようにアセットを内蔵するのは遅延削減というより安定性・カスタマイズ性・初回ロード改善に効く**。真の入力遅延削減は AudioContext 設定と即時描画が支配的で、今回その両方を実装しました。

## 差し替え方法

```bash
# 例: 自作タップ音を置く（短いWAV推奨）
cp ~/my_hit.wav assets/tap.wav

# 例: 自作ノーツ画像を置く
cp ~/my_note.png assets/note.png
cp ~/my_ln.png assets/note_ln.png
```

差し替え後はリロードで自動反映されます。
